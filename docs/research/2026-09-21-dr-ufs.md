# Ultimate Frontend Skills (6.0.1) — pre-release review and competitive comparison

**Scope note (budget cutoff):** This run dispatched 17 scrapers (5 codebase, 12 web) at tier `thorough`. All 17 ultimately returned (the last 2 arrived after synthesis had already begun under budget pressure and are folded in below). The formal Step-5 multi-voter verification stage was skipped entirely due to budget; confidence markers below instead reflect each scraper's own source-quality self-report (primary fetch vs. search-snippet-only vs. blocked fetch), which most scrapers recorded explicitly.

## Executive Summary

Ultimate Frontend Skills (UFS) 6.0.1 is a large, actively-engineered plugin: a 496-line main SKILL.md that correctly defers its "nine-stage pipeline" and all heavy content to 26 on-demand reference files (10,432 lines total), a real headless-Chrome render checker and AI-slop audit script whose detection list closely tracks the external "AI tells" ecosystem that emerged in 2026, and a JSON-registry pack mechanism that vendors and modifies two third-party skill packs under recorded licenses[^1][^4][^5][^13][^50]. Its weak points are almost all hygiene rather than substance: the Codex and Claude manifests have already drifted (different description text, missing `$schema`, no mirrored `interface`/skills metadata), AGENTS.md's own documentation is stale, the 444-site reference corpus carries no license/fair-use statement, and the "game" and "app" extensions are research prose rather than a genuinely separate chassis, despite SKILL.md pitching "three surfaces" sharing one route[^19][^20][^21][^22][^3][^10]. Against the field, UFS sits closer to Anthropic's own frontend-design skill in ambition (avoid generic AI aesthetics) but is an order of magnitude larger per-invocation than frontend-design's reported ~50-line SKILL.md, while vercel-labs' web-design-guidelines, emilkowalski/skills, Impeccable and taste-skill each solve a narrower slice (review-only, animation-only, slop-detection-only) and are all already public with five-figure GitHub star counts, which UFS is not yet[^56][^60][^62][^63][^64].

## Key points

### 1. Progressive disclosure is real, but the entrypoint itself is heavy · Confidence: high
The main SKILL.md (skills/ultimate-frontend-skills/SKILL.md) is 496 lines / ~5,022 words with a ~545-character description and no `allowed-tools` field; it explicitly delegates the nine-stage pipeline and all deep content to `references/*.md`, and the repo's own AGENTS.md states the rule directly: "Keep SKILL.md short. Depth belongs in references/, which is only read when needed. Frontmatter is loaded into every session; the body is not."[^1][^3] But 496 lines / ~5k words is far larger than Anthropic's own frontend-design skill, third-party-reported at roughly 50 lines[^56][^57]. The 26 reference files total 10,432 non-blank lines, several individually exceeding 1,000 lines (ui.md 1,108; craft.md 1,153; three.md 1,170)[^1][^5].

### 2. The AI-tells audit is unusually well-aligned with the live 2026 "slop-detection" ecosystem · Confidence: high
`scripts/audit.mjs` checks for emoji, fake data, marketing "slop copy," a fixed SLOP_FONTS list (Inter, Instrument Serif, Space Grotesk, Geist, Syne, DM Sans, Poppins, Fraunces), a SLOP_HEX regex for the "VibeCode purple"/Tailwind-blue palette, gradient-text, italic-accent-phrase overuse (>1 per page), and pill badges above `<h1>`[^13]. This maps almost one-to-one onto what independent 2026 tools catalogue: Impeccable's PR #129 (merged May 2 2026) added rules for exactly "oversized italic serif hero" and "hero eyebrow chip" patterns[^51]; 925Studios (Sep 19 2026) and prg.sh separately flag Inter and purple-to-blue gradients as the defining AI tells[^52][^53]; solodesign.cc (Jun 6 2026) flags "eyebrow chrome" and italic flourishes "without content justification"[^54]. UFS's own audit was written independently of these but converges on the same signal set.

### 3. The reference corpus (444 sites) has real crediting but no license/usage statement · Confidence: high
CREDITS.md is auto-generated from `data/awards.json` and lists every entry as `[Name](URL) - Studio, Year - source`, grouped by award source (Awwwards 123, editorial 114, FWA 39, etc.), totaling "444 sites, 12 packs"[^10]. Entries carry a `verified` flag and unverified rows are dropped at merge time[^3][^11]. No screenshots or scraped images of the 444 sites are stored in the repo — it is links + metadata only[^10]. However, no license, fair-use, or "links-only" statement exists anywhere for this corpus; the repo's MIT LICENSE covers only UFS's own code[^10][^12]. Several entries are already marked "(offline when last checked)" and have not been pruned[^10].

### 4. Manifest hygiene has already drifted between Claude and Codex · Confidence: high
`.claude-plugin/plugin.json` and `.codex-plugin/plugin.json` agree on name/version (6.0.1, no version drift) but diverge on: `$schema` (present in Claude's manifest, absent from Codex's), the `description` text (verbatim different wording between the two), and the `keywords` array (different sets)[^20][^21]. Only `.claude-plugin/marketplace.json` carries a `skills` path field and an `interface` block (displayName, capabilities, brandColor, etc.) — there is no Codex-side equivalent, and AGENTS.md itself documents this as a deliberate "Codex reads this too" decision rather than an oversight[^22][^3]. Separately, `hooks/hooks.json` declares one `UserPromptSubmit` hook using the Claude-specific `${CLAUDE_PLUGIN_ROOT}` variable, with no Codex-side equivalent[^25]. AGENTS.md's own repo-layout documentation is stale: it lists only 5 of the 6 files actually in `commands/`, omitting `security-check.md`[^3][^26].
**External spec confirms the drift is out-of-policy, and reveals a bigger runtime gap.** Anthropic's official plugin-reference docs state plugin.json permits "only eight fields," with "CI validation rejects any plugin.json containing additional properties," and that `name` is the only required field while `version` should be bumped every release "so updates are intentional"[^74]. UFS's two plugin.json files already diverge on `description` and `keywords` — exactly the kind of drift the 8-field/CI-validated schema is meant to prevent[^20][^21]. Separately, docs confirm all component directories (`commands/`, `agents/`, `skills/`, `hooks/`, etc.) must sit at the plugin root beside `.claude-plugin/`, never inside it, and that non-skill component changes (hooks, `.mcp.json`, agents) do not take effect until `/reload-plugins` or a restart — only SKILL.md edits apply immediately[^74]. marketplace.json's own required fields are `name`, `owner`, and `plugins[]` (each needing `name`+`source`), with an optional `strict` flag controlling whether the marketplace entry alone can substitute for a plugin.json[^75]. On the Codex side, the manifest is `.codex-plugin/plugin.json` and AGENTS.md itself is a vendor-neutral, frontmatter-free convention used by 60k+ projects and resolved nearest-file-wins[^76][^77]. Most importantly: an open OpenAI GitHub issue documents that "Codex plugin docs/examples imply plugin-local hooks, but runtime only executes global hooks.json"[^78] — meaning UFS's `hooks/hooks.json` UserPromptSubmit nudge (already Claude-only by variable choice, see §4 above) may not be executable on the Codex side at all even if ported, not just unmirrored. True parity would require either moving that hook's logic to Codex's global hook layer or accepting it as Claude-only and documenting that explicitly, rather than silently omitting it.

### 5. Game and app "extensions" are research documents, not a separate chassis · Confidence: high
SKILL.md pitches "Three surfaces: a website, an app, a game" sharing "the same route, the same chassis and the same audit"[^1]. In practice, `scripts/webdesign.mjs` contains a code comment stating "Each preset is only a token override. The chassis never changes," and its four presets (fable/bone/ink/cinema) are all website-oriented — there is no game or app preset, no canvas/WebGL start-screen template, and no native-app-chrome runtime[^19]. `references/games.md` and `references/apps.md` are long comparative-analysis documents (549+ and 548 lines) cataloguing real game start screens and 35 shipped apps for their "tells," with verbatim quoted CSS/copy from external sites, but contain no reusable CSS classes or boilerplate of their own[^17][^18].

### 6. The packs mechanism is a JSON registry with selective vendoring, not skills.sh-style install-on-demand · Confidence: high
`skills/ultimate-frontend-skills/data/packs.json` records 11 registered third-party packs (fields: id, kind, skills, licence, added, sha for vendored ones); `packs/` physically contains copies of only 2 of them (microsoft/playwright-cli and bergside/awesome-design-skills), each with a generated `UFS-NOTES.md` documenting real changes made (corrected font-weight claims, added missing "font source" fields, fixed a naming collision with `pbakaus/impeccable`)[^6][^7][^8]. `packs vendor` explicitly refuses non-permissive licenses unless forced, checked against an allow-list (MIT/Apache-2.0/CC0/Unlicense/BSD-2/3/MPL-2.0)[^7]. This is a fundamentally different model from skills.sh, which is a public install-time registry (`npx skills add owner/repo`) with no local copy, no re-licensing check beyond an optional frontmatter `license` field, and no "improvements" concept — vendoring is closer to what one `vercel-labs/skills` GitHub PR calls a "vendor-skill" pattern used by at least one other marketplace author[^70][^71][^8][^72].

## Findings

### What the model reads per use
Only two real SKILL.md files exist in the repo: the 496-line main one and a 77-line `visual-research` sub-skill[^1][^2]. Everything named "atelier," "awards," "debug-website," "design-handoff," "security-check," "webdesign" is a slash **command** (`commands/*.md`), not a skill with YAML frontmatter[^1]. The nine pipeline stages (BRIEF, BENCH, REFERENCES, ROUTE, ASSETS, CHASSIS, COPY, CHOREOGRAPH, VERIFY, SHIP — ten labels for "nine stages," stage 0 through 9) live entirely in `references/pipeline.md`, cited from SKILL.md as "First. The nine stages, the gates, and the route decision that stage 3 makes"[^1][^4].

### Typography, colour, motion — current external practice (2026)
Fluid type scales via `clamp()` and the newer `interpolate-size` property (Chromium 129+ only as of the fetch date) are current Baseline-adjacent practice, alongside `text-wrap: balance` (headings) and `text-wrap: pretty` (body, not yet in Firefox)[^27][^28][^33]. Variable fonts are now the default choice for any project that controls font selection, paired with `size-adjust`/`ascent-override`/`descent-override` on fallback declarations to cut CLS[^30]. OKLCH is shadcn/ui's default token color space as of its Tailwind v4 migration, with light/dark themes implemented as swapped OKLCH values on the same token names rather than separate palettes[^34][^35]. WCAG 2.2's 4.5:1/3:1 ratio-based contrast model remains the only *ratified* standard — WCAG 3's APCA-based contrast model is still a W3C Working Draft with its contrast section pulled since 2023 and full Recommendation status not expected until roughly 2028–2030, so teams treating APCA as already-normative carry compliance risk[^39][^40][^41]. Cross-document View Transitions ship in Chrome/Edge 126+ and Safari 18.2+ but remain MDN "Limited availability," not Baseline; scroll-driven animations (`animation-timeline: scroll()`/`view()`) are supported in all four major engines and are now described as production-ready[^42][^43][^44]. `prefers-reduced-motion` guidance in 2026 favors *replacing* motion (fade instead of scale/parallax) over stripping it entirely, plus an in-page opt-in toggle alongside the OS media query[^12 note: see ^ list]. *(UFS's own typography.md/motion.md/imagery.md rule text was not read in this pass — whether it actually encodes clamp()/oklch()/animation-timeline/text-wrap is an open question, see Contradictions below.)*

### Reference corpus, audits, render/parity checks
`scripts/inspect.mjs` drives real Chrome/Edge/Chromium headless over raw DevTools Protocol (no Playwright/Puppeteer, by explicit AGENTS.md constraint), checking overlaps, offscreen/overflow content, contrast, collapsed elements, and broken images by walking the actual rendered box tree[^14]. `scripts/parity.mjs` compares a built page against a Claude Design canvas by detecting the canvas's `appifact-doc` JSON state block or `<x-dc>` artboard markers, deliberately targeting CDP subframe contexts to avoid measuring the sandboxed editor chrome instead of the real design[^15].

### Packs vs. skills.sh
skills.sh is a public, Vercel-run registry ("think of it as an app store for AI agents") supporting 11+ agent platforms via `npx skills add owner/repo`, with SKILL.md frontmatter limited to `name`/`description` (both required) plus optional `license`/`compatibility`/`metadata` — no enforced version field, versioning is convention-only inside `metadata`[^71][^72]. It reports 600,000+ listed skills and a public install-count leaderboard, explicitly trading curation for reach[^73]. UFS's packs.json is a private, opinionated alternative: fewer entries, explicit license-gating before vendoring, and a documented-diff ("UFS-NOTES.md") requirement for anything actually copied in[^6][^7][^8].

### Competitive landscape (September 2026)
- **Anthropic frontend-design** — official Claude Code plugin, ~50-line SKILL.md (third-party-reported), five stated Design Principles (Hero Element, Typography, Visual Structure, Motion, Content) plus a named "Generic AI Design Tells" section (cream+terracotta, SaaS card kits, tracked-out labels), used as Claude's automatic default for frontend work[^56][^57].
- **Claude Design** — separate Anthropic Labs product (launched Apr 17 2026, Opus 4.7-powered visual canvas), moved research-preview→beta Jun 17 2026 with a `/design-sync` two-way bridge to Claude Code; not a skill at all, a hosted GUI product[^58][^59].
- **vercel-labs web-design-guidelines** — not a standalone repo; it's a skill inside `vercel-labs/agent-skills` that dynamically fetches a 103-item condensed rule sheet from the separate `vercel-labs/web-interface-guidelines` repo (~850 stars, MIT) at review time rather than bundling rules[^60][^61].
- **emilkowalski/skills** — 12 skills (animate, animate-expo, review-animations, apple-design, write-swift, etc.), MIT, roughly 37.5k–39.6k GitHub stars (snapshot-dependent), installed via `npx skills@latest add`[^62].
- **Impeccable** (pbakaus) — cross-harness (Claude Code, Gemini CLI, Codex CLI, Cursor, Copilot) deterministic design-constraint system, 64 slop patterns, 23 commands, reportedly ~50k GitHub stars (unverified, search-aggregated)[^50][^63].
- **taste-skill** (Leonxlnx, MIT, Vercel OSS-sponsored) — tunable DESIGN_VARIANCE/MOTION_INTENSITY/VISUAL_DENSITY parameters; name is ambiguous, at least 3 unrelated repos share it[^64].
- **awesome-design-skills** — 67-skill registry pairing SKILL.md (machine rules) with DESIGN.md (human intent) per style; identical content appears under 3 different GitHub usernames, an unresolved duplication signal[^66].
- **superdesign** — canvas-based AI design agent (IDE extension + companion `superdesign-skill`); its own comparison blog frames awesome-design-skills as "a static rulebook" applied blind with no render preview, versus its own live canvas[^67][^68][^69].

UFS is the only one of these that bundles a 444-site *credited* reference corpus, a headless render checker, and a Claude-Design parity checker in one plugin — none of the others do all three — but it is also the only one not yet public, so it carries no adoption signal to weigh against the others' star counts.

## Contradictions & Open Questions

- Whether UFS's typography.md/motion.md/imagery.md actually specify the current CSS mechanisms found in external research (`clamp()`, `oklch()`, `color-mix()`, `animation-timeline`, `text-wrap`, `prefers-reduced-motion` fallback patterns) was not directly checked — only that these files exist, with line counts (typography.md 268 lines, motion.md 353 lines, imagery.md 310 lines)[^1]. This is the single most important open question for a "correctness of rules" verdict and should be the first thing read in any follow-up pass.
- Whether UFS's `hooks/hooks.json` nudge hook would even execute if ported to `.codex-plugin/` is unresolved: OpenAI's own GitHub issue tracker shows plugin-local hooks are documented but not currently executed by the Codex runtime[^78], so mirroring the hook file alone (recommendation #6 below) may not be sufficient — this needs a live Codex test, not just a file copy.
- Reported GitHub star counts for Impeccable (~50k) and taste-skill (~46k+) come from aggregated search-engine summaries, not a direct fetch of either repo's stargazer count — treat as directional, not exact.
- `awesome-design-skills` and `taste-skill` both have multiple, seemingly-duplicate repos under different GitHub usernames; which is canonical was not resolved by any scraper.

## The ten highest-value changes, ranked by value per effort

1. **Fix the Claude/Codex manifest drift** — align `.codex-plugin/plugin.json`'s `$schema`, `description` text, and `keywords` with `.claude-plugin/plugin.json`; trivial edit, directly fixes a hygiene issue a public-release reviewer would flag immediately[^20][^21].
2. **Update AGENTS.md's own repo-layout list** to include `commands/security-check.md`, which it currently omits — a five-minute doc fix that removes a stale-docs red flag[^3][^26].
3. **Add an explicit license/fair-use statement for the 444-site corpus** before public release — currently CREDITS.md states intent ("nothing is copied") but no formal terms exist anywhere in the repo; this is the single clearest legal-exposure gap found[^10][^12].
4. **Prune or auto-flag dead corpus links** — several entries already carry a manual "(offline when last checked)" note; wire this into the existing `verified` flag/merge step instead of leaving stale rows in CREDITS.md[^10][^11].
5. **Resolve the impeccable naming collision and the unsourced "Anthropic Sans" claim** inside the vendored `bergside-awesome-design-skills` pack — UFS's own notes flag both issues already; finishing the correction is small and directly on-brand for a plugin whose entire pitch is catching unsourced/fake claims[^8].
6. **Mirror `interface`/skills metadata and a Codex-equivalent of the `UserPromptSubmit` nudge hook into `.codex-plugin`** for genuine cross-runtime parity, since today only the Claude side gets discoverability metadata and the nudge hook[^22][^25][^3].
7. **Add a CI test that asserts field parity** across `.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`, and `marketplace.json` — the existing test suite (5 files, real headless-browser fixtures, cross-platform CI matrix) is strong but has no test guarding against the drift found in #1/#6 recurring[^23].
8. **Do a line-level correctness audit of typography.md/motion.md/imagery.md** against current CSS mechanisms (clamp/oklch/color-mix/animation-timeline/text-wrap/prefers-reduced-motion) — the one substantive open question this research could not close; directly determines whether the "correctness of rules" claim in any public announcement is honest.
9. **Either build a real distinct game/app chassis or soften the "three surfaces, same chassis" language** — right now SKILL.md's pitch is stronger than what `scripts/webdesign.mjs` actually ships (one shared chassis, four website presets, no game/app template); repositioning is nearly free, building the real thing is a larger project — do the honest wording fix first, then decide on scope for the real build.
10. **Trim the main SKILL.md body itself** — at 496 lines/~5k words it is roughly 10x Anthropic's own frontend-design skill; since progressive disclosure is already correctly used for reference material, the next lever is shrinking what's paid on *every* invocation before any reference file is opened.
